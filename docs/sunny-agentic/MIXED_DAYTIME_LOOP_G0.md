# Sunny G0: mixed voluntary daytime choices after reviewed P1-help WATER

**TEST-ONLY / INERT / G0.** This additive behavior slice belongs to [Issue #56](https://github.com/niabchan/stardew-ai-agent/issues/56). It **stacks on independently G0-accepted [Draft PR #93](https://github.com/niabchan/stardew-ai-agent/pull/93)** at pinned `ac87aac4c896377b44db161f23aae26ceb115bb4`; this new branch changes **only** `reference/sunny_mixed_daytime_g0.py`, `mod/tests/test_sunny_mixed_daytime_g0.py`, and this document. No existing live Mod, accepted Host, WATER policy, controller or L2/L3 planner is changed or merged.

## What existed and what was missing

- Existing [Draft PR #58](https://github.com/niabchan/stardew-ai-agent/pull/58) has `FakeGame` + `OfflineController` for synthetic P2 `MOVE_TO_CHAIR` or `STAY`, with pending unknown outcome quarantined.
- Existing [Draft PR #60](https://github.com/niabchan/stardew-ai-agent/pull/60) has `FakeDaytimePlanner` contextual proposal filtering; it alone does not execute effects.
- Existing [Draft PR #61](https://github.com/niabchan/stardew-ai-agent/pull/61), **a separate parallel branch**, already joins L2 fake chair action with L3 contextual choice. It does **not** exist in this PR #93 stack, and is deliberately **not copied** into this branch.
- Independently source-accepted [Issue #94 G0 R2](https://github.com/niabchan/stardew-ai-agent/issues/94#issuecomment-7062109098) covers `FakePermissionedWaterBridge`: P1-managed crop, a separately fixture-provisioned standing P1→P2 `WATER` grant, fake Host budgets, STOP, revocation and unknown pending. That alone does not implement a **mixed-interest** activity chooser.

The **new difference** is a very small optional mixed daytime composition: at each new *synthetic* revision propose `STAY` / `MOVE_TO_CHAIR` / **permitted** `WATER`, let a bounded *scripted test interest* select any offered activity, pass the selected action to the appropriate existing G0 fake executor, check its exact fake result, and only consider a next interest after the source supplies a newer observation. Unlike PR #61's chair-only flow, this tests mixing P1-help WATER with another P2 daytime choice.

## Explicit fake scenario

1. A deterministic fixture places Sunny P2 at `(4,4)`, next to the fictional P1-managed dry crop `(4,5)`, and independently provisions a one-tile WATER grant into the SAME fake Host. The fake L2 game and fake Host must share exact epoch and owner. Synthetic weather `sunny` is **explicitly provided** by the test; the L2 world alone cannot prove weather. No P1 diary/private chat or P1 direct controls are available to the interest callback.
2. On revision 1, the candidates are `STAY`, `MOVE_TO_CHAIR`, `WATER`. A synthetic interest chooses `WATER`. The accepted G0 policy verifies fake A/B effect and operation-matched fake receipt. The mixed coordinator **does not itself declare the soil wet or advance the revision from an ACK**.
3. The test-owned *fake observation publisher* explicitly supplies revision 2 and a newly wet soil reading. On this newer scene, WATER is no longer eligible, but `MOVE_TO_CHAIR` remains a voluntary choice. Its existing L2 fake controller observes P2 tile change from `(4,4)` to `(7,4)`; this is **movement to a chair tile**, **not proof of sitting down**.
4. The fake world provides revision 3 after successful movement. Sunny can now independently choose `STAY`, with no new dispatch. No rigid 09:00 start, fixed daily schedule, single action/day cap or forced speech. A separate test verifies two distinct P1-approved crop tiles can be watered under a two-start/two-tile fake Host grant, then Sunny chooses movement and STAY.

## Safety and limits

- This code runs **only** in the in-memory Python fake models. The real Mod, Windows DLL, SMAPI, HTTP/IPC adapter, production Host, external model chooser, actual game state, P1 consent UI and native WATER remain entirely **unimplemented/unproven**.
- The P1 crop owner tag is never permission. The fake Host grant must already have been independently test-provisioned. The synthetic planner additionally cross-checks P2 fake tile is actually one Manhattan step from the crop rather than trusting `adjacent=True` alone.
- `WATER` is not inserted into the plain L3 planner's authorized candidate set: it is added only after the accepted fake Host grant/soil/epoch/owner/day/tile checks. No HARVEST, PLANT, bulk water, SPEAK_TO_P1, arbitrary TV or FIREPLACE action is offered. STAY is always available on a valid new scene.
- Any unresolved attempt in **either** `FakeGame` or `FakeHostWaterFence` blocks all further actions. A newly constructed coordinator referencing the same objects cannot drop pending or revive a consumed snapshot. STOP blocks even chair movement. Chooser-side world/ledger/grant changes are rejected before fake dispatch; a valid revocation fixture notice is still latched.
- The toy coordinator's `run_bounded` makes at most four deterministic sequential attempts and stops on STAY, denial, error or unknown outcome. The supplied `after_verified` callback is a **test-controlled source of invented observations**. No fabricated soil change, new revision or automatic retry happens without it. An exception in that callback ends the bounded run.
- The two existing fake dispatchers **do not** share one real atomic cross-action Host A/B gate, credential, durable journal or cross-process STOP. Fake chair movement is not posture evidence. These limitations matter even though their unit tests pass. No external provider is called; simulated interests are not a trained model's independent agency. This is a gameplay contract demonstration, **not** actual Sunny choosing activities in a running farm.
- In-memory counters and revisions can be modified by arbitrary Python callers. The fixture cannot authenticate P1 approvals, provide privacy/isolation against a compromised process, or establish real physical STOP/quiescence, actual tool footprints, effect evidence or full action-route coverage.

## R1 response to independent Issue #96 FIX_REQUIRED (not yet re-reviewed)

The independent [source-cited review](https://github.com/niabchan/stardew-ai-agent/issues/96#issuecomment-7077394363) found two counterexamples despite green first-head CI:

1. **Mutable chair destination not present in the fake L2 Observation.** A chooser could change the fake `game.chair_tile` while keeping the same observed revision/options, and L2 would dispatch and then verify against the new target. The R1 coordinator now snapshots and strictly validates the synthetic chair tile separately from the L2 observation, rechecks it after the chooser and before dispatch, checks it again inside the toy L2 choice callback, and refuses to declare `VERIFIED_FAKE` unless the post-L2 P2 tile and chair target still match the originally pinned destination. A discovered post-dispatch mismatch sets a same-FakeGame shared quarantine flag, returns `UNKNOWN_UNVERIFIED_CHAIR_TARGET`, and blocks later coordinator instances. There is no actual chair sit/stand evidence.
2. **Lost revocation on erroneous chooser exit.** A chooser could install a valid inactive higher revision of P1's WATER grant and then raise or return HARVEST/another invalid choice. R1 uses `try/finally` to ingest the valid revocation into the *unchanged* accepted fake Host permission store on **every chooser exit**, before invalid interest or exception results. The old active grant cannot be reprovisioned and cannot authorize WATER at a later fake scene revision. The coordinator also catches a failed second fake observation read after a selected choice before any dispatch.

Additional R1 defensive checks validate exact synthetic observation field types before revision/coordinate arithmetic and lock subsequent decisions on the SAME FakeGame if a test-controlled post-verification observation publisher partially mutates the world and raises. This is toy quarantine, not real cross-process persistence. Tests directly exercise the original changed-chair and invalid/raising chooser traces, revision-2 grant restoration, changed destination during fake dispatch, failed observation reread, malformed observations and partial publisher failure. Positive mixed daytime and budget/STOP paths are retained.

**Remaining known boundaries:** This code has two separate, sequential fake action executors, not one atomic runtime Host. The destination is stable only under the observed single-threaded synthetic sequence; direct Python mutation between guards, a malicious in-process fixture and real concurrency are not solved. Quarantine after a toy L2 'verified' target mutation is a fail-closed local result, **not** a durable real-world effect receipt or authenticated stopping mechanism. Independent source review of this changed exact head and exact-head CI are required before any G0 acceptance. Native WATER `BLOCK/DENY`, real Host A/B `PROPOSED_UNWIRED`, and `NO_GO_G1_START / NO_GO_LIVE_G2` remain unchanged.
## R2 response to independent Issue #96 R1 STOP-bypass review

The independent [source review #7077790388](https://github.com/niabchan/stardew-ai-agent/issues/96#issuecomment-7077790388) confirmed the R1 chair-target and chooser-exit-revocation fixes, but found a new **sequential fake Host STOP bypass**: the second `game.observe()` could latch Host STOP (or a Host pending WATER operation) without changing any game observation fields. R1 checked the shared gate **before**, but not **after**, this read, so it could still dispatch fake P2 chair movement and return `VERIFIED_FAKE`.

R2 adds a fresh mixed Host gate check **after** the second observation, then wraps the existing *unchanged* `OfflineController`'s game view in `_HostGatedChairWorld`. The small fake-only adapter rechecks the shared Host STOP/epoch/owner/pending fence and pinned chair destination at L2's own observation, **before and after** its `prepare` admission, and **before and after** its `dispatch`. A newly latched STOP or pending Host operation *during* the fake `prepare` observation retires the reserved fake Game attempt as rejected **before effect**; an unexpected Host transition *during* `dispatch` is instead treated as **UNKNOWN** because an effect may already have started. Final fake verification also checks the guard, and the existing shared Game pending/quarantine then blocks new coordinators. The adapter allows only its own current Game attempt ID to be pending; unrelated Game pending attempts remain denied.

Added direct regression for STOP, Host WATER pending and Host epoch rotation on the **second observation** without a new Game revision: all must stop before fake chair dispatch. More tests inject STOP into L2's **first** observation, the Game's `prepare` observation and the Game's `dispatch` observation, plus a Host pending WATER record installed after Game prepare. The latter dispatch-start case deliberately asserts **unknown pending with possible residual fake chair movement**, not an impossible assertion that an already-entered fake effect was canceled.

**Model limitation:** These checks demonstrate sequential revalidation for the documented synthetic callbacks. They do not establish atomic physical STOP, a shared real A/B checkpoint for chairs and WATER, thread-safe lease acquisition, actual SMAPI tool-route coverage, durable effect evidence or real chair sit/stand. An arbitrary in-process test actor can still mutate fixtures during or after the guard. This is still G0-only pending new exact-head CI and independent source review; PR #93 accepted source remains unchanged. Native WATER `BLOCK/DENY`, Host A/B `PROPOSED_UNWIRED`, 11 G1E OPEN, 50 canonical G1/G2 `not_run`, `NO_GO_G1_START / NO_GO_LIVE_G2` stay frozen.
## R3 response to independent Issue #96 R2 WATER retarget finding

The independent [R2 source-cited FIX_REQUIRED review](https://github.com/niabchan/stardew-ai-agent/issues/96#issuecomment-7078055504) confirmed the earlier STOP, chair target, and chooser-exit revocation counterexamples had been addressed. It then found a separate **WATER crop-switch** trace: on the second `FakeGame.observe()` call, a test fixture can replace a granted, P2-adjacent crop at `(4,5)` with a different granted crop at `(8,4)` (four Manhattan steps from fake P2 at `(4,4)`) and matching stewardship **without changing the game observation or crop revision**. The existing reviewed WATER bridge would accept `crop.adjacent=True` for the replacement. The prior mixed-layer independent P2-position check applied only when offering WATER, not immediately before dispatch.

R3 fixes this in **the three new additive PR #95 G0 files only**. The mixed loop now remembers the exact `crop`, `stewardship`, `ledger` and `grant` instances selected before the interest callback. **After the second observation**, before entering the accepted fake WATER bridge, `_water_still_admitted` revalidates their identity, the pinned game epoch/owner/revision/position/role/readiness, the **actual Manhattan distance of exactly one tile** from the previously observed fake P2 location, the fake Host STOP/pending/identity and the original fake bridge's crop/grant/soil checks. No grant allowlist, crop `owner_tag`, or manually set `adjacent=True` can replace the independent positional evidence. This helper ingests valid P1 revocation notices on failed checks. The second observation call additionally ingests valid revocation in `finally`, including if that observation callback raises.

To guard the exact pre-B boundary in this deterministic model, the unmodified accepted `FakePermissionedWaterBridge.step` receives a small synthetic stage callback at `after_wait`, `after_reserve`, and `before_b` that repeats the P2 location and original crop/permission tests. The callback tolerates only the expected reserved operation on this same fake Host. If the fake context changes before reservation, the bridge returns `DENIED_WAIT_FAILURE` without an effect. If changes happen after reservation but before B, it retains `UNKNOWN_PENDING` and **never enters B**; it does not pretend an unresolved reservation is safely cleaned up. Post-B residual effects and receipts remain constrained only by the accepted fake Host model.

Dedicated regressions include the **exact four-step granted crop swap** on the second read, a second permitted adjacent crop, and even a new equal-valued crop object without a new observation: all must block without Host reservation, spent attempts, or fake effects. Pre-B injected fake P2 movement at each of `after_wait`, `after_reserve` and `before_b` must avoid fake effect and budget debit, leaving pending quarantine where reservation already exists. Additional regressions verify P1's valid inactive notice is recorded if delivered in the second observation whether the read returns normally or raises.

**Still G0-only and pending fresh independent source review.** The sequential injected hooks, fake crop, P2 coordinates, permissions, scripted interest, Host STOP, and receipts are not authenticated real-game observations or native atomic authorizations. This does not prove real pathfinding, sitting, Windows/SMAPI/HTTP compatibility, durable journaling, concurrent STOP, or live P1 consent. PR #93's independently accepted head is unchanged. `NO_GO_G1_START / NO_GO_LIVE_G2`; Native WATER `BLOCK/DENY`; real Host A/B `PROPOSED_UNWIRED`, 11 G1E OPEN, 50 canonical G1/G2 `not_run` remain in force.
