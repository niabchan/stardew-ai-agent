## Minimum migration design for the specific pilot (proposal, not authorization)

1. **Client transport adapter first (offline-only):** move all Python game HTTP calls behind one injectable adapter for endpoint/port, separate game credential, P2 session header, read scope, timeouts and response classification. Prefer changing the PowerShell wrapper to expose an explicit `-GameUrl` that validates loopback; do not start by monkey-patching module global constants. Keep OpenAI Responses API credentials isolated from game credentials.
2. **Safe initialization and ownership:** introduce one P2 controller startup handshake with server-issued authenticated owner/session for the current epoch; no implicit takeover. Keep the existing per-save local lock as defense in depth, not sole authority. Define lost-initialize-response recovery and clean owner release (P12 long-running calls may still be active).
3. **Define minimal observations before enforcement:** map current fields of P1/P2 roles, activity, room/tile, relevant menu/night flags, world readiness, clock, pause/freeze, bedtime capability, P2 mailbox and feed evidence. Implement server-side allowlisting, minimal P1 safety booleans or explicit human consent, and protect log/diary access separately. This is **not** the anonymous OBS viewer model.
4. **Read requests versus mutations:** allow only approved read operations to retry with bounded backoff. For mutations, write the durable dispatch marker before sending, then on timeout/401/reload mark outcome unknown until reconciled, without resending. Keep existing content/isError/structuredContent JSON parsing compatibility while introducing explicit transport/status errors.
5. **Reload fences:** require a source-authoritative host load epoch and bounded P2 lease generation; game-thread guard checks epoch/role/owner before queued execution and further coroutine steps. Old ledger/fingerprint alone cannot enforce this. Do not permit automation of human P1.
6. **Migration tests with fake transport:** 8770/18770 selection and wrong-instance detection; 401/403/409/429; direct `tools/call` refused before init; handshake, 202 notifications and DELETE, header storage/revocation; JSON-RPC ID reuse without action dedup; offline P1-gift safety field projection; read retry vs never-retry ambiguous `respond`/`go_to_bed`; freeze/status contact; long wait and lost response; repeated same-save Reload. No live testing until explicitly approved.
7. **Staged rollout:** a later Code PR should adapt the private Python pilot **offline first** (not committed as raw ZIP) and add a compatible server adapter/tests in separate reviewable PRs. Only then build without deploying, and use an isolated backed-up `Test_` save in a separately approved Windows smoke test. Do not change `main` or installed DLL from this report.

## Explicitly not verified

- This archive proves a concrete **v0.3.11 code snapshot**, not the operator's current installed launcher or any edits outside the ZIP.
- It does not prove external Luna model availability, successful responses with future authentication, a complete MCP-version handshake, browser/OBS and runner compatibility, a Windows listener's network reachability, or real-game correctness of queued action cancellation.
- The private archive **contains Python and PowerShell sources plus tests**; it was inspected statically. Source-reading did not use any game endpoint or AI provider credentials.
- Real security fixes in PRs #19–#24 are **not implemented**; synthetic fixtures and this design report do not make the legacy HTTP server secure.

**Review decision:** This audit clears the “external client uninspected” blocker **for the supplied v0.3.11 snapshot only**, not for whatever is currently installed. Next implementation should begin with narrowly scoped offline transport compatibility tests and a client/server contract, not immediate production auth enforcement or gameplay changes.
