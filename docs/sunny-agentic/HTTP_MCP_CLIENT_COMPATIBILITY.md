## Request contracts requiring deliberate migration

1. **Routes and methods.** `AgentHttp.Handle` serves read endpoints (`/api/state`, `/api/feed`, `/api/day`, `/api/days`, `/api/memory`, `/api/relationships`, `/api/stats`, `/api/briefing`) with **no method check**; `/api/control` uses GET for flags and POST for mutations; `/api/meta` and `/api/release_freeze` require POST; `/api/debug/*` requires config opt-in and POST. Overlay and Replay currently need browser reads. A future explicit method allowlist must be accompanied by a compatibility test rather than reusing PR #21's P2-only model for all paths.
2. **MCP wire protocol.** `/mcp` aliases host P1; `/mcp/p2` works only when split screen and resolved P2 role AI. A **single** JSON-RPC message with an id gets a `Mcp-Session-Id: stardew-p2` response header, not a verified caller session; batch responses omit that header, all-notification requests return **202 with no body**, DELETE returns 200 but performs no teardown. A client can call tools without initialize. These are legacy contracts to inventory, **not** security features to preserve unchanged.
3. **MCP side effects.** `HandleMcp` reads whole body, calls `SessionBreaks.Observe`, assigns seat-wide `ReplyWithinSeconds` from `?reply_within=`, then dispatches; `McpDispatcher.Dispatch` calls `MarkContact` before examining method/id/params. Contact sets `Connected=true`, clears timeout and freeze-release state. Discovery/notifications can therefore change clock eligibility. Proposed auth, parse and session checks must precede every mutable step; merely filtering tool names is not enough.
4. **Different meanings of session.** Current `SessionBreaks` is a *context-window/planned-tool-break* mechanism controlled by `?breaks=1` or config, with `initialize` resetting break bookkeeping. A future security **owner session + save epoch** must be a separate, explicit concept. Preserve documented break markers and legitimate voluntary continuation without granting takeover or replaying stale actions.
5. **Result compatibility.** The server returns `content` text, `isError`, and optional `structuredContent` for tools; errors may be result-level or JSON-RPC/HTTP failures. Pending calls can outlive HTTP clients; no real disconnect cancellation is wired. Scope unauthorized/expired/stale-session errors distinctly from game-world tool results. Never automatically retry a mutation if completion is ambiguous.
6. **Origin and browser submission.** Removing `Access-Control-Allow-Origin: *` does **not** stop all browser requests. Explicitly deny untrusted Origin/Host/peer, simple `text/plain` POSTs and malformed requests *before effects*. Origin alone is **not** a native-client credential; same-origin browser viewers must still have least-privilege grants.
7. **Sensitive response fields.** Local `Select-Object` projection only hides output in PowerShell; it does not stop `GET /api/state` returning the full host snapshot. `/api/feed` carries all-seat state/log, `/api/day` includes diary entries and `/api/memory` includes notes. A client-side `?player=p2` overlay filter also does not limit transmitted data. Future read grants should use server-side projection.
8. **Configured identity.** Current default seats are P1–P3 AI and single-screen; a short/malformed role config can fall back to AI. Guy's human P1 protection is an explicit configuration and runtime invariant to test, not a global default.

## Decisions required before implementation

- **D1: Viewer authentication.** Choose and test a browser/OBS-safe view-only mechanism (e.g., separate local read-only broker or operator-authenticated same-origin session); do **not** hardcode a controller bearer in served JavaScript, put it in URL `?api=`, or grant a viewer command access. A strict native-only Origin policy in the current test fixture is not suitable for the overlay as-is.
- **D2: Controller identity and epoch.** Single P2 controller is intended; define authenticated owner, session creation/expiration, graceful restart, SaveLoaded/ReturnedToTitle invalidation, queued-call cancellation and role checks at execution. A predictable legacy `Mcp-Session-Id` is not an auth credential. A synthetic one-session fixture cannot alone prove strong identity under concurrent real clients.
- **D3: Read scopes.** Separate minimal watchdog and status, private diary/replay, P2 agent data, and operator control. Determine exactly which P1 fields the human consents to share and which never enter Luna/overlay.
- **D4: Compatibility fallback.** Prefer explicit migration and fail-closed errors to a hidden no-auth mode. Explain how existing native and browser clients obtain grants without recording secrets in the repo, URL, logs or screenshots.
- **D5: External source review.** `PILOT_AUDIT_V0311.md` confirms portions of a historical v0.3.11 ZIP (e.g., P11/P13 status and respond, Python loop lock) but **not** the current HTTP wrapper or installed pilot. The source is not in the GitHub checkout. Do not assume headers, request batching, retries, or secure credential storage until checked.
